# Build and Packaging

build.js drives esbuild over exactly one entry, src/renderer/index.js, emitting an IIFE bundle at dist/renderer/bundle.js for browser platform targeting chrome120, sourcemapped and unminified with NODE_ENV defined as development; pixi.js bundles in whole (external list empty) so the renderer has no runtime module resolution. package.json's build script then performs a step esbuild cannot do: copying src/renderer/audio/pcm-processor.js verbatim into dist/renderer/, because AudioWorklet.addModule requires a standalone script URL - index.html loads ../../dist/renderer/bundle.js while MicCapture loads ../../dist/renderer/pcm-processor.js ([[Audio Pipeline]]). The same copy logic doubles as the guard ensuring the worklet file always ships alongside the bundle.

Distribution goes through electron-builder.yml under appId com.gemvtuber.app, productName GemVTuber, copyright 2025, output into dist/. Its files whitelist packs only src/**, assets/**, models/default/**, and package.json - so packaged builds carry whatever model sits in models/default but not user-added folders like ren_pro_en or Allium企划, and not the vendored Cubism core either since git ignores it (packaging follows the filesystem, not git, so a locally present live2dcubismcore.min.js under src/renderer/lib does ship as part of src/**). Platform targets are NSIS assisted-install plus portable on Windows (icon.ico), dmg on mac (icon.icns), AppImage plus deb on Linux (icon.png); NSIS allows custom install directories and creates a desktop shortcut. Scripts expose npm run package per-OS. The Cubism SDK itself is never bundled by policy - README states users must comply with Live2D's licensing for their own models, which pairs with .gitignore's exclusion of the core library ([[Workspace Files]]).
