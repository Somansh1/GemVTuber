# Avatar Rendering

AvatarManager wraps a PIXI.Application initialized with backgroundAlpha 0 (true transparency over the desktop), devicePixelRatio resolution, resizeTo window, and a ticker capped at 30fps. Rendering uses pixi.js 8 with untitled-pixi-live2d-engine/cubism: Live2DModel.registerTicker(PIXI.Ticker) runs at import time and Live2DPlugin joins the extension registry before renderer init. loadLive2DModel first guarantees window.Live2DCubismCore - loading the vendored lib path is implied but the code falls back to injecting the cubism.live2d.com CDN script and, if that fails too, resolves anyway rather than rejecting so the app degrades to the default avatar instead of crashing. Models arrive as local:// URLs (the main-process protocol), are loaded with autoHitTest/autoFocus/autoUpdate, fitted to the window at ninety percent padding times a scaleMultiplier defaulting to 5.0 (a fudge constant compensating small model canvases), and start their idle motion by fuzzy group-name match on idle/breathe.

discoverCapabilities is the feature that makes any model work without per-model config: it walks coreModel.parameters handling both Cubism 4 structured arrays (ids, minimumValues, maximumValues, defaultValues) and Cubism 2 getParameterId-style APIs, coerces parameter IDs that arrive as objects (.s/.id/_id/[0] fallbacks - a defensive workaround for WASM string interning), lists expression names from settings, counts motion groups, and derives capability flags like hasBody from ID substrings, with mouth parameters recognized under both Cubism generations. The profile feeds tool generation ([[Tool Calling]]). Parameter writes go straight to the core model inside try/catch, and a hook on internalModel 'afterModelUpdate' fires lip sync then forces coreModel.update() so mouth overrides recalculate the mesh before the draw call.

triggerExpression resolves generously: exact name first, then case-insensitive substring fuzzy match both directions (LLM says "happy", file says "Happy.exp3"), then index lookup. Eye follow consumes the global mouse stream from main ([[Electron Main Process]]), converting through model.toLocal and normalizing distance within 800px into the engine's focus controller. DefaultAvatar is the no-dependency fallback: a Canvas2D character with eight emotions, breathing, blinking, eye tracking, and a compatible getCapabilities profile so LipSync drives it identically. One hard limit surfaces as a user-facing error: Cubism 5 exports are unsupported, with a subtitle advising re-export for Cubism 4.2. Back to [[Home]].
