# Tool Calling

ToolDefinitions.js generates the function-calling surface dynamically from what the loaded avatar can actually do. generateTools(modelProfile, customActions) aspires to five candidates filtered by Boolean: set_avatar_emotion only when expressions exist (semantic emotion string); play_avatar_motion when motion groups exist (group plus index); play_custom_action listing custom action names as an enum; take_screenshot (no parameters, described for curiosity-driven looks at the screen); and remember_context taking a note string for durable user facts. The same module exports generateSystemInstruction, which assembles the prompt sent at setup: personality text first, then an "Your Avatar" section enumerating available expressions and motion groups with encouragement to use them frequently, a Behavior section (be conversational, comment on screens naturally without being creepy, keep responses concise for voice, use remember_context), then optional Recent Screen Observations and Things You Remember sections fed from PersonalityEngine.

The load-bearing subtlety: procedural animation was deliberately removed from this surface. A comment above getCustomActionTool reads that generating valid procedural keyframes was unreliable for an LLM, generateSystemInstruction carries a matching "(Removed procedural animation instructions)" marker, and git pins the removal to commit aab5aa9. Consequently animate_avatar is never offered today even though index.js still contains its dispatch case calling proceduralAnimator.playAnimation - a dead branch - and the file also still holds a full set of unused create* factory functions below generateSystemInstruction (enum-constrained emotion/motion tools, createAnimateTool, createScreenshotTool) left over from the earlier design. Worse for the feature's survival: ProceduralAnimator.loadCustomActions has no caller anywhere, so getCustomActionNames() is always empty and play_custom_action is never generated either. The README nonetheless still advertises AI-composed animations and a custom-actions JSON format as headline features - [[Discrepancies]] records the full gap.

Dispatch lives in index.js's onToolCall handler: set_avatar_emotion maps through triggerExpression with fuzzy name matching, play_avatar_motion through triggerMotion, take_screenshot reuses ScreenAnalyzer.requestCapture so the model sees fresh pixels, remember_context appends to memory, each result acknowledged via sendToolResponse with a success flag and human-readable message. Because tools are baked into setup, changing personality or loading a new model triggers a full session reconnect rather than an incremental update. Back to [[Home]].
