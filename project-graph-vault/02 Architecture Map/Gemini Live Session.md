# Gemini Live Session

GeminiLiveSession in the renderer speaks the BidiGenerateContent WebSocket protocol directly - no @google/generative-ai SDK, a stated choice for maximum control and minimal bundle size. connect() opens wss://generativelanguage.googleapis.com/ws/...BidiGenerateContent with the API key in the query string and immediately sends one setup message: model (default models/gemini-2.5-flash-native-audio-preview-12-2025), generationConfig pinning responseModalities to AUDIO with a prebuilt voice (default Aoede; the JSDoc lists Charon, Fenrir, Kore, Puck as alternatives), systemInstruction text, and functionDeclarations wrapped in a tools array when non-empty. The connect promise resolves only on setupComplete, and _retryCount resets there so backoff state survives reconnects.

Outbound traffic has four shapes. sendAudio wraps 16kHz Int16 PCM into realtimeInput mediaChunks tagged audio/pcm;rate=16000, base64-encoding through 32KB String.fromCharCode batches; sendImage posts bare JPEG mediaChunks; sendImageWithPrompt instead builds a clientContent user turn combining inlineData image plus text "to prevent context detachment" - screen observations ride this path ([[Screen Awareness]]); sendText is the plain clientContent turn. sendToolResponse answers a function call by id with { output: result }. All sends funnel through _sendMessage guarded on connection state, a structure introduced by the PR #20 centralization refactor.

Inbound routing handles setupComplete; serverContent where an interrupted flag triggers the barge-in callback (the renderer empties the speaker queue), modelTurn parts split into audio inlineData chunks for playback and text parts that both hit the chat log file and the UI callback, and inputTranscription/outputTranscription likewise persisted; and toolCall.functionCalls iterated into {name, args, callId} for dispatch ([[Tool Calling]]). Resilience comes from auto-reconnect: any close other than code 1000 within three attempts schedules reconnect at 2^attempt seconds, while disconnect() zeroes _maxRetries so intentional shutdowns never resurrect the socket.
