# Lip Sync and Animation

LipSync derives mouth movement purely from the output audio's AnalyserNode, never from text or timing metadata. Each update computes RMS over the time-domain buffer, scales by eight, clamps to one, and eases toward the target with a 0.35 smoothing factor; after ten frames below 0.02 volume the value decays by 0.85 per frame so the mouth closes gracefully instead of snapping. The smoothed value drives the discovered MouthOpenY parameter. Vowel shaping comes from frequency bins: low (0-8 bins, roughly 0-350Hz), mid (8-24, ~350-1050Hz), high (24-50, ~1050-2200Hz) energies combine into formTarget = ((high - low) / total) * 0.8, smoothed at 0.25 and applied to MouthForm only while volume exceeds 0.05 - loud low-frequency energy rounds the mouth toward "ah/oh", high-frequency energy widens it toward "ee". It is deliberately rough vowel estimation, not viseme mapping.

The binding strategy is the subtle part: for Live2D models index.js assigns avatarManager.onLipSync so updates fire inside the engine's afterModelUpdate hook - before physics and mesh rebuild, with an explicit coreModel.update() forcing the override into the draw ([[Avatar Rendering]]) - while a requestAnimationFrame fallback ticker drives only the DefaultAvatar path when no Live2D model is loaded.

ProceduralAnimator plays keyframe animations over Live2D parameters: playAnimation sorts keyframes by t, resolves an easing function (linear, ease-in, ease-out, ease-in-out, or ease-out-bounce), repeats as directed, and interpolates each frame via requestAnimationFrame between adjacent keyframes with sensible fallback interpolation for out-of-range progress. Its hot loop was optimized during the campaign recorded in .jules/bolt.md ([[Timeline]]): segment parameter arrays are precomputed once instead of allocating Sets every tick, benchmarked around fifty-three percent faster. loadCustomActions can register named JSON actions and playCustomAction runs them - but no code ever calls loadCustomActions, so at runtime the animator is reachable only through the dead animate_avatar dispatch case; both the engine and the custom-action tool are effectively dormant, as [[Discrepancies]] details. stopAll cancels all in-flight animation frames.
