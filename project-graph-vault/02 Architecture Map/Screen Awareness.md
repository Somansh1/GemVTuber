# Screen Awareness

Screen awareness runs on two cooperating halves with intentionally different jobs. In main, ScreenCaptureService is pure scheduling: start(intervalMinutes) defaults to seven and each cycle re-arms setTimeout with the base varied plus-or-minus thirty percent so captures land unpredictably; firing does nothing but send trigger-periodic-capture to the renderer. Its captureNow method (854x480 desktopCapturer thumbnail, JPEG quality 40, async disk write under userData/logs/screenshots) exists for the capture-screen IPC but currently has no renderer caller - preload exposes captureScreen, yet every live path goes through the renderer's own grab instead.

That renderer half is ScreenAnalyzer. On the periodic trigger it calls requestCapture: getScreenSourceId via IPC, then getUserMedia with chromeMediaSource 'desktop' at 854x480, one frame drawn to canvas, exported as JPEG quality 0.4, saved to disk via saveScreenshotLog, and finally onCapture. The same requestCapture serves on-demand looks from the context menu's Screenshot action and the take_screenshot tool call, making it the single funnel for everything Gemini sees. onCapture stores the lightweight reference in PersonalityEngine ([[Personality and Memory]]) and, if connected, sends the image through sendImageWithPrompt bundled with a strict instruction: observe the desktop, speak ONLY on critical or concerning activity changes, never describe literally, never hallucinate, output nothing otherwise - a prompt engineered so ambient captures stay silent instead of narrating the user's screen every few minutes.

Two privacy-relevant facts fall out of the code: every capture, periodic or requested, is persisted unencrypted as screenshot_*.jpg with no retention limit, and the images cross the WebSocket to Google whenever the session is up. The user-facing controls are the screenCaptureEnabled toggle and captureIntervalMinutes slider in settings, whose save path stops and restarts the scheduler in main. Back to [[Home]].
