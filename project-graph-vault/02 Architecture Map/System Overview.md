# System Overview

GemVTuber runs as two cooperating processes. The Electron main process owns the native surface: a transparent frameless always-on-top BrowserWindow (400x600, resizable down to 200x200, skipTaskbar, no shadow), a system tray with show/hide and click-through lock, the config file, chat/screenshot logging, and a randomized screen-capture scheduler. The renderer is a single esbuild IIFE bundle loaded by src/renderer/index.html that contains everything else - mic capture through an AudioWorklet, PCM playback, the Gemini WebSocket client, PixiJS Live2D rendering, lip sync, keyframe animation, settings panel, and overlay UI. The only bridge between them is preload.js's contextBridge object electronAPI; contextIsolation stays on and nodeIntegration off.

index.js wires the renderer in a fixed order: UI panels first, then AvatarManager plus ProceduralAnimator and either the auto-discovered default Live2D model or the Canvas2D fallback avatar, then AudioPlayer at 24kHz and MicCapture, then LipSync, then PersonalityEngine, then saved config, UI callbacks, the lip sync loop, and finally tryAutoConnect if an API key exists. connectGemini builds the tool declarations from the discovered model profile and the system instruction from personality, screen context, and memories; after setupComplete it starts mic streaming and periodic screen analysis. From there the live loop is continuous: 16kHz mono Int16 PCM flows up as realtimeInput mediaChunks, 24kHz PCM audio comes back inline and is scheduled gaplessly into the speakers, function calls arrive out-of-band and are executed then acknowledged via sendToolResponse, and interruptions clear the playback queue instantly for barge-in.

Latency and smoothness are protected by a consistent set of choices: no SDK over the raw BidiGenerateContent WebSocket ([[Gemini Live Session]]), AudioWorklet processing off the main thread with batched zero-copy buffer transfers, fire-and-forget ipcRenderer.send for chat logs, async filesystem calls in main so directory scans never stutter, a 30fps cap on the Pixi ticker, and lip sync applied inside the engine's afterModelUpdate hook so mouth overrides recalculate the mesh before each draw. Screen awareness rides the same session rather than a side channel - captures are sent as clientContent turns paired with a strict observe-or-stay-silent prompt, described in [[Screen Awareness]].
